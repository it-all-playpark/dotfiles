fix: 🐛 不発だった permission 規則を撤去し未使用 skill を絞る

実挙動テストで permissions.deny の一部が機能していないことが判明したため、
不発の規則を撤去し、必要な保護は PreToolUse hook 側に集約する。

## 実測で確認した事実（v2.1.233, macOS）

発火する規則: Bash(wget:*) / Bash(npx:*) / Bash(rm -rf:*) /
Bash(git push --force:*) — いずれも末尾 :* のみの単純前置形。

発火しない規則: Bash(nc :*) ← nc -h が実行された。
Bash(cp /*:*) / Bash(cp * /:*) / Bash(cp -R * /:*) / Bash(mv /*:*)
← 該当コマンドが素通り。内部に * を持つ形は一致しない。

交絡は排除済み: permissionDecision allow を返す hook は allow-pr-merge.sh
（gh pr merge 限定）と allow-feature-push.sh（git push 限定）の 2 本のみで、
cp/mv/nc には関与しない。

公式ドキュメントも「Bash permission patterns that try to constrain command
arguments are fragile ... Use PreToolUse hooks」と明記しており、引数依存の
禁止は permission 規則では表現できない。

## 変更

### 1. Bash(nc :*) -> Bash(nc:*)
末尾スペースのせいで一度も発火していなかった。netcat が実質ノーガード
だったため修正する。

### 2. 不発の deny 規則 24 件を撤去（190 -> 164、npx/pnpx の 2 件を含む）
- 保護ブランチ push 10 件（Bash(git push *:main) 等）
- Bash(git push origin :*)（末尾スペースで不発）
- cp / mv / rsync / tar / unzip / ditto / Bash(rm -r /*) の 13 件

いずれも書き直し不能（宛先が末尾引数のため前置形で表現できず、完全一致では
全綴りの列挙が必要）。残すと「暴走コマンドはブロックされている」という誤った
安心を生むため撤去する。動作する前置形の Bash(rm -r /:*) は残した。

保護ブランチについては hook が素の git push origin main / git -C <dir> push /
git push origin :main / --delete main を deny、--mirror / --all を ask と判定
することを直接実行して確認済み。deny 側が補っていたものは無い。

### 3. npx / pnpx の deny を撤去し allow の死に設定を削除（22 -> 20）
Bash(npx:*) deny と Bash(npx vitest run*) allow が併存していたが、deny は
allow に常勝するため後者は追加当初から一度も機能していなかった（実測: allow に
完全一致する npx vitest run も拒否された）。

代わりに pretool-npx-guard.sh（本ブランチの先行コミットで追加済み）を登録し、
vitest 実行と vdelta run のみ素通し、それ以外の npx / pnpx は deny する。
任意リモートパッケージ実行のガードは維持したまま vitest が通るようになる。

deny 規則を「多層防御」として併置することはできない。deny は allow に常勝
するため、Bash(npx:*) を残すと hook が素通しを決めても vitest が実行できない。

### 4. 未使用 skill 26 件を user-invocable-only に（21 -> 47）
journal（2026-05-07〜08-16、4540 レコード）を集計したところ、登録 skill 82 件の
うち 64 件が一度も起動されていなかった。既に off の 21 件を除く 43 件が候補。

このうち 17 件は RULES.md（memvid / repo-export / session-load / session-save）
または他 skill の SKILL.md から参照されており（skill-retrospective は 170 箇所）、
モデルから隠すとパイプラインが壊れるため除外した。残り 26 件を
user-invocable-only にする（/name でのユーザー起動は残る）。

skill listing は既定で context の 1%（skillListingBudgetFraction = 0.01）に自動
圧縮されるため、未使用分を外すと自動発火させたい skill の説明文に予算が回る。

### 5. RULES.md
Git 節の「permissions.deny でも重ねて塞いである」を実態に合わせ、hook が唯一の
強制点であることと、撤去の根拠を明記した。
